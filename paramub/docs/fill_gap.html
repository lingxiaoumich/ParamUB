Post-processor

Gap fill — shell ↔ UB ribbon strip

Triangulate the open ribbon between the upper-body shell rim and the parametric underbody rim. One subdivided slant per UB-rim vert, bipartite-zip ribbons that share slant verts so the UB side comes out watertight; intentional polygon holes on the shell side are passed to an optional MeshLab close_holes + remesh pass.

Why this is its own step

After run_shell.py peels the upper shell off a reconstructed whole-car mesh and integrate_underbody.py drops in a parametric underbody trimmed to the shell silhouette, the two surfaces meet at a thin open ribbon along the rocker line and around each wheel arch. Shell rim has ~3.7 k boundary verts; UB rim has ~1.9 k. They almost meet in 3-D but the trim leaves an open seam at most points and a wider gap at the wheel arches.

fill_gap.py closes that seam. It is run as the third stage of the pipeline:

  1. run_shell.py → upper shell + meta
  2. integrate_underbody.py → shell + parametric UB (trimmed) + per-wheel STLs, all in the shell frame
  3. fill_gap.py → gap-fill ribbons + combined STL of shell + UB + ribbons

Algorithm — shared-slant ribbons + bipartite zip

  1. Extract the longest open boundary of each input mesh. The walker in paramub.shell.recut.find_open_boundary_components is robust to the 21-or-so degree-4 T-junctions the shell rim has around wheelhouse openings.
  2. For each UB-rim vert u_j, pick its apex apex_j = the nearest shell-rim vert by 3-D distance, then subdivide the line u_j → apex_j into K_j segments at ~target_edge_mm spacing (default = shell median edge length, typically ~6 mm). The intermediate verts are stored ONCE per slant and reused by both ribbons that touch u_j.
  3. For each UB rim edge (u_j, u_{j+1}), triangulate the ribbon between slant[j] and slant[j+1] by bipartite zip — at each step advance whichever slant pointer yields the shorter next diagonal, emitting one triangle per step. The zip handles per-slant K mismatches automatically. Because slant[j] is the right side of ribbon (j-1, j) AND the left side of ribbon (j, j+1), the two triangles either side of each interior slant edge meet with matching verts ⇒ no wedge holes between ribbons.
  4. The resulting gap mesh has two boundary types:
    • UB-rim edges (u_j, u_{j+1}) — shared bit-exact with the UB rim, so concat with UB closes them.
    • Apex-chain edges (apex_j, apex_{j+1}) when the two are different shell verts — these are open on the shell side. Combined with the shell-rim arcs between consecutive apices, they form well-shaped polygon holes that close_holes can fill.
Why the apex chain misses shell rim verts — apex selection is nearest-neighbour per UB vert, not a 1-to-1 mapping. With 3.7 k shell verts and 1.9 k UB verts, most shell verts are not anyone's nearest. They stay on the shell rim and become part of the shell-side polygon-hole boundary.

Usage

conda activate paramub

# 1. Just the gap mesh (no combined output, no repair)
python fill_gap.py \
    --shell outputs/integrate/<base>_shell.stl \
    --ub    outputs/integrate/<base>_underbody_trimmed.stl \
    --out   outputs/integrate/<base>_gap.stl

# 2. Also concatenate shell + UB + gap into a combined STL
python fill_gap.py \
    --shell outputs/integrate/<base>_shell.stl \
    --ub    outputs/integrate/<base>_underbody_trimmed.stl \
    --out          outputs/integrate/<base>_gap.stl \
    --combined-out outputs/integrate/<base>_combined.stl

# 3. Combined + MeshLab close_holes + isotropic remesh (needs the
#    conda env's libstdc++ for PyMeshLab):
LD_LIBRARY_PATH=$CONDA_PREFIX/lib python fill_gap.py \
    --shell outputs/integrate/<base>_shell.stl \
    --ub    outputs/integrate/<base>_underbody_trimmed.stl \
    --out          outputs/integrate/<base>_gap.stl \
    --combined-out outputs/integrate/<base>_combined.stl \
    --repair --repair-close-holes-max 10000 \
    --repair-remesh-mm 6 --repair-remesh-iters 3

Outputs

FileWhenContents
<out> (e.g. _gap.stl) always The ribbon mesh alone. Vertex set is [shell rim | UB loop | shared interior slant verts]; shell- and UB-rim positions are bit-exact with the source meshes so they merge cleanly on concat.
<combined-out> (e.g. _combined.stl) --combined-out Shell + UB + gap concatenated and run through trimesh.process=True (merges duplicate verts). Has shell- and UB-rim edges closed by the ribbon, with residual open edges only on the apex-chain polygon boundaries on the shell side.
(in-place rewrite of <combined-out>) --repair Repaired combined mesh — merge close verts, fix non-manifold edges, close_holes, optional isotropic remesh, then re-seal.

Console output reports edge health at each stage so you can see how far each step gets, e.g.:

[ribbons] 1,935 slants  (K min/median/max = 8/17/18)  → 62,658 tris
[check]   combined: f=1,090,463  open edges=5,093  non-manifold=1,053
[repair]  final:    f=1,229,742  open=1,327  non-manifold=44   # repair, no remesh
[repair]  final:    f=1,722,502  open=0      non-manifold=1    # repair + remesh 6 mm

Repair pipeline

--repair drives PyMeshLab's meshing_merge_close_vertices → meshing_repair_non_manifold_edges → meshing_close_holes on the combined mesh. Optionally followed by meshing_isotropic_explicit_remeshing (when --repair-remesh-mm > 0) and a final non-manifold + close_holes re-seal to clean up edges the remesher opens.

The close_holes triangulator (Liepa's min-weight DP from vcglib) fans each closed boundary loop. On the well-shaped shell-side polygon holes it produces a tidy fan; on a fan-pivot region it can leave a visible radial pattern. Running with --repair-remesh-mm 6 isotropically rebuilds those triangles to match the shell density and hides the fan.

Recommended one-shot recipe for a watertight result: 

LD_LIBRARY_PATH=$CONDA_PREFIX/lib python fill_gap.py \
    --shell outputs/integrate/<base>_shell.stl \
    --ub    outputs/integrate/<base>_underbody_trimmed.stl \
    --out          outputs/integrate/<base>_gap.stl \
    --combined-out outputs/integrate/<base>_combined.stl \
    --repair --repair-close-holes-max 10000 \
    --repair-remesh-mm 6 --repair-remesh-iters 3

Tuning knobs

flagdefaultmeaning
--ribbon-target-mm 0 (auto) Spoke-axis subdivision target edge length. 0 ⇒ auto from shell median edge length. Lower ⇒ denser ribbon, smaller triangles, finer fit; higher ⇒ coarser ribbon, less RAM.
--repair-close-holes-max 10000 Max number of boundary edges per loop that MeshLab will attempt to close. The shell-side polygon holes here have up to a few hundred verts each, so 10 000 is plenty of headroom.
--repair-remesh-mm 0 (off) Isotropic remesh target edge length (mm). 0 = no remesh. 6 mm matches the typical shell density and is the recommended default when remeshing.
--repair-remesh-iters 3 Number of explicit isotropic-remesh iterations. 3 is enough to fan-break a close_holes patch and even out triangle sizes; more (up to ~6) gives a slightly smoother result at roughly linear cost.

Known limits

  • Apex sharing creates non-manifold edges. When many consecutive UB verts pick the same shell vert as their nearest (common in tight wheel-arch corners), several ribbons converge at one apex and the edges meeting at the apex have >2 incident faces. Variant-G (repair + remesh) typically reduces these to 1 non-manifold edge across the whole car; pymeshlab cannot fully eliminate them without re-splitting verts. If the downstream consumer needs a strict 2-manifold solid, follow up with trimesh.repair.fix_normals + pymeshlab.meshing_repair_non_manifold_edges(method=1) (split mode) to duplicate the offending vertices.
  • Close_holes fans can produce a long thin sliver triangulation on highly non-convex polygon holes. The optional isotropic remesh hides this; without it the fan is visible.
  • Inconsistent winding. The bipartite-zip emits ribbon triangles in zip order, not necessarily aligned with the shell/UB outward normals. Add trimesh.repair.fix_normals downstream if you need consistent winding.
