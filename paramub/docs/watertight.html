Post-processor

Watertight finisher — Blender smooth remesh + trimesh extract

Turn the fill_gap-combined STL (~1 M tris, ~5 k open edges, ~1 k non-manifold edges, hundreds of micro-bodies) into a strictly watertight, bilaterally symmetric, single-body STL suitable for CFD, 3-D printing, and volume computation.

Why this is its own step

fill_gap.py seals the ribbon between shell and UB rims and (with --repair --repair-remesh-mm) produces a mesh with zero open edges. But its output is still not strictly watertight in the sense that downstream consumers expect:

  • It typically has a handful of non-manifold edges (apex-sharing in the ribbon strip, plus a few residuals from PyMeshLab's close_holes fan triangulation).
  • Face winding is inconsistent — the ribbon-zip emits triangles in zip order, not aligned with the shell / UB outward normals.
  • The mesh has hundreds of disconnected micro-bodies (left over from the variant-M ribbon plus PyMeshLab artifacts), so even though the BIG body is closed, trimesh.is_watertight on the raw STL returns False.

These three things together are what real CFD / 3-D-print toolchains refuse. This stage is a robust post-processor that makes the result pass trimesh.is_watertight == True, is_winding_consistent == True, and len(split()) == 1 in one shot.

Pipeline

Input STL (non-watertight, many bodies, gaps)
        │
        ▼
   ┌─────────────────────────────────────────────────┐
   │ STAGE A : Blender (bpy 4.2)                     │
   │  1. import STL                                  │
   │  2. Smooth Remesh modifier (dual-contouring,    │
   │     octree depth N, scale 0.99)                 │
   │  3. keep largest connected component            │
   │  4. merge-by-distance / dissolve-degenerate /   │
   │     fill_holes / normals consistent             │
   │  5. symmetrize at y=0 (NEGATIVE_Y)              │
   │  6. iterative non-manifold edge cleanup         │
   │     (max --max-nm-passes; exits on convergence) │
   │  7. keep largest connected component again      │
   │  8. export STL  (<stem>_fixed.stl)              │
   └─────────────────────────────────────────────────┘
        │
        ▼
   ┌─────────────────────────────────────────────────┐
   │ STAGE B : trimesh                               │
   │  9. split STL by connected components           │
   │ 10. keep the largest body (drops Blender STL    │
   │     float32 micro-strays)                       │
   │ 11. verify watertight + record metrics          │
   │ 12. export STL (<stem>_clean.stl) + JSON report │
   └─────────────────────────────────────────────────┘
        │
        ▼
Output - <stem>_clean.stl   strictly watertight, single body
       - <stem>_clean.json  verify report

Smooth dual-contouring is the core because it produces a closed iso-surface from any input triangle soup and merges nearby disconnected parts as long as they sit within ~bbox / 2^depth of each other. The symmetrize pass folds left/right asymmetries and provides a free Y-symmetry guarantee. The delete-non-manifold-edges-and-refill loop handles the few 3-face edges the remesh leaves behind.

Install

bpy 4.2 ships as a pip wheel and coexists in the existing paramub conda env alongside cadquery / trimesh / pyvista. rtree is also needed for the optional reference-distance metric in the verify report: 

conda activate paramub
pip install bpy==4.2.0 rtree

Verify with python -c "import bpy, rtree; print(bpy.app.version)". Without rtree, the pipeline still produces a strictly watertight STL — only the dist_remesh_to_orig_mm / dist_orig_to_remesh_mm fields of the JSON verify report are skipped (with a single console warning).

Usage

Stage 4 of the reconstructed-car pipeline. Recommended setup is one Slurm node at depth 11 (~96 GB Blender peak); see make_watertight.sbatch for the 128 GB / 8 CPU / 3 h wrapper.

Slurm (default — production depth 11)

sbatch make_watertight.sbatch \
    outputs/integrate/<base>_combined.stl \
    <tag>

Default depth is 11. The wrapper requests 128 GB / 8 CPUs / 3 hours on the standard partition and writes Slurm logs under logs/. Any extra args after the tag are forwarded to make_watertight.py (e.g. --no-symmetrize, --depth 12).

Login-node quick-check (depth 8, ~15 s)

conda activate paramub
python make_watertight.py \
    --input  outputs/integrate/<base>_combined.stl \
    --output outputs/integrate/<base>_clean.stl \
    --depth 8          # validates pipeline; ~0.8 mm error, 9 MB out

Use this to sanity-check the install or to iterate quickly while tuning other flags. The production result lives at depth 11 (~0.4 mm error, 611 MB out) and needs the Slurm wrapper.

Python API

from paramub.watertight import make_watertight

report = make_watertight(
    "outputs/integrate/<base>_combined.stl",
    fixed_stl   = "outputs/integrate/<base>_fixed.stl",
    clean_stl   = "outputs/integrate/<base>_clean.stl",
    report_json = "outputs/integrate/<base>_clean.json",
    reference_stl = "outputs/integrate/<base>_combined.stl",
    depth=11,
)
print(report["is_watertight"], report["volume_m3"])

Outputs

By default the stage processes both the body (from <base>_combined.stl) and the 4 wheel STLs that integrate_underbody.py wrote adjacent to it (<base>_wheel_{front_left, front_right, rear_left, rear_right}.stl). The wheels go through a fast trimesh-only finisher (fill_holes + biggest body + verify) since each one is already single-component and consistent-winding from the CadQuery tessellation; only a handful of chord-discretization open edges need closing. Pass --no-wheels to disable.

FileContents
<stem>_fixed.stl Blender-stage output for the body. Closed per Blender's topology check, but typically retains 2–6 face micro-strays from STL float32 vertex rounding. Useful for debugging the Blender stage in isolation.
<stem>_clean.stl Final strictly-watertight, single-body, bilaterally symmetric body STL.
<stem>_clean.json Verify report for the body — vertices / faces, watertight, winding, Euler number, bbox, surface area, volume (if watertight), and (when a reference STL is given) symmetric point-to-surface distances in mm.
<stem>_wheel_<corner>_clean.stl One per wheel (front_left / front_right / rear_left / rear_right). Strictly watertight, single body, ~222 k tris each (~11 MB). The trimesh-side fill_holes only adds the missing closure triangles; mean distance to the source wheel STL is ≈ 1e−12 mm.
<stem>_wheel_<corner>_clean.json Verify report per wheel.

The cleanup loses ~0.3 mm of fidelity at any depth: symmetrize averages small left/right asymmetries, and the non-manifold fix deletes ~150-400 face neighbourhoods and refills them with simpler patches.

Watertight check semantics

After stage B, the clean STL satisfies: 

m = trimesh.load(clean_stl, force="mesh")
assert m.is_watertight          # every edge has exactly 2 incident faces
assert m.is_winding_consistent  # face normals point outward consistently
assert len(m.split()) == 1      # exactly one connected component
m.volume                        # well-defined m³ * 1e9
Note on Euler / genus. A watertight mesh can have any genus. For the test car we get euler = -10 at depth 11, i.e. genus 6 — the surface has 6 through-tunnels (wheel wells, cabin opening, intake/exhaust). This is expected and does not mean the mesh is broken; it just means the closed surface is topologically a 6-handled solid rather than a sphere.

Tuning knobs

flagdefaultmeaning
--depth N 11 Octree depth for Smooth Remesh. 2^N cells across the longest bbox axis. Memory/time scale ~8× per +1.
--scale F 0.99 Remesh modifier grid scale (0..0.99). Lower = more bbox padding.
--no-symmetrize off Skip the y=0 symmetry pass.
--symmetry-direction NEGATIVE_Y Source side for symmetrize: NEGATIVE_Y keeps y<0 and mirrors to y>0. Other axes / signs accepted.
--no-fix-nonmanifold off Skip the delete-NM-edges-and-refill loop.
--max-nm-passes N 20 Cap on non-manifold fix iterations. Loop exits early when NM / boundary / NM-verts hit 0.
--merge-distance MM 1e-3 Vertex merge threshold (mm). Also used by symmetrize's seam weld and dissolve_degenerate's threshold.
--fill-sides N 16 Max hole size (in edges) for fill_holes. The non-manifold-fix loop uses 4 × N for the larger refilled holes.
--n-samples N 30 000 Points sampled per surface for the surface-distance metrics in the verify report.
--reference PATH --input Reference STL for distance metrics. Defaults to the same file as --input; pass an empty string to skip.
--include-wheels / --no-wheels on Process the 4 adjacent wheel STLs through a fast trimesh-only fill_holes + verify pipeline. Default ON. Wheels share the input's base name (e.g. <base>_combined.stl → <base>_wheel_<corner>.stl).

Known limits and tweak points

  • Genus is not controlled. If you need a genus-0 (sphere-topology) result, add a pre-step that closes through-tunnels: a Solidify modifier with a thickness larger than the largest tunnel, or an OpenVDB morphological close.
  • Non-manifold convergence is heuristic. The delete-and-refill loop has always converged in our tests (≤ 8 passes), but a pathological input could hit the cap. If --max-nm-passes is exhausted without convergence, the Blender stage output will still have a small number of non-manifold edges; the trimesh stage will then report is_watertight == False. Either raise --max-nm-passes or pre-process with a coarse voxel remesh.
  • STL float32 round-trip. Stage B reliably catches the 2–6 face micro-strays Blender's STL exporter introduces. If a downstream consumer re-saves the STL through a non-process=True loader, the artifacts may re-appear; consider exporting .ply or .obj instead, where each vertex is stored once.
  • Symmetry axis. Y is hard-coded as the symmetry-direction default. For inputs whose symmetry plane is not y=0, pass e.g. --symmetry-direction NEGATIVE_X.
  • Memory. Depth 12 was not tested; expect ~50 M tris and ~30 GB peak just for the bpy data structures. Increase --mem in make_watertight.sbatch accordingly.
