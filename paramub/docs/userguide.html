User guide

ParamUB

Parametric car underbody generator built on CadQuery. One dataclass in, STL + preview out. Optional front splitter and rear diffuser are constructed as multisection Bezier lofts.

Install

conda activate paramub        # provides cadquery, pyvista, trimesh, matplotlib

Quick start

from paramub import generate, UnderbodySpec

generate(
    UnderbodySpec(),              # defaults: 2.7 m wheelbase, 225/45 R18, etc.
    output_dir="outputs/demo",
    stem="ub",
    output_mode="all",            # "stl"  -> just ub.stl
                                  # "all"  -> ub.stl + ub_preview.png + ub.log + ub.json
    output_parts=True,            # also emit FLOOR.STL + WHEEL_FL/FR/RL/RR.STL
    export_step=True,             # also emit ub.step  (+ part STEPs when output_parts)
)

Outputs

FileWhenContents
<stem>.stlalways Merged assembly (floor + wheelhouses + 4 wheels).
<stem>_preview.pngoutput_mode="all" 8-panel composite: iso, top, front elevation, Y=0 section, front+rear axle sections, front+rear tire details, plus parameter footer.
<stem>.logoutput_mode="all" Mirrored stdout/stderr.
<stem>.jsonoutput_mode="all" Full spec tree as JSON (including any splitter/diffuser sections).
FLOOR.STL, WHEEL_FL.STL, WHEEL_FR.STL, WHEEL_RL.STL, WHEEL_RR.STL output_parts=True One STL per assembly part. Filenames are fixed UPPERCASE. The FLOOR part uses a finer angular tolerance so the multisection Bezier loft tessellates smoothly (see floor_angular_tolerance_rad below).
<stem>.stepexport_step=True Merged BREP STEP file with named subparts (no tessellation; opens cleanly in any CAD tool).
FLOOR.STEP, WHEEL_FL.STEP, … WHEEL_RR.STEP export_step=True + output_parts=True One STEP per assembly part.

Tessellation tolerances

generate() argDefaultMeaning
stl_tolerance_mm 0.1 Linear chord tolerance — controls flat-surface chord error.
stl_angular_tolerance_rad 0.1 Angular chord tolerance applied to the merged STL and to per-part wheel STLs. Coarser ⇒ faster, smaller files.
floor_angular_tolerance_rad 0.02 Finer angular tolerance applied ONLY to the FLOOR per-part STL (and the merged STL's body face, via a body pre-mesh trick). Keeps the multisection-diffuser Bezier loft smooth without making the wheel parts pay the cost.

Spec layout

One root spec composes the whole thing. Edit any subspec independently.

UnderbodySpec
├── vehicle plan          wheelbase_mm, front_overhang_mm, rear_overhang_mm,
│                         track_front_mm, track_rear_mm
├── ride / floor          ride_height_mm, floor_width_mm, floor_angle_deg
├── diffuser (legacy)     diffuser_start_x_mm (None = rear axle),
│                         diffuser_angle_deg, diffuser_radius_mm
├── splitter+diffuser     splitter_sections: list[SplitterSection] | None
│   (multisection)        diffuser_sections: list[DiffuserSection] | None
│                         When set, the corresponding piece is a Bezier
│                         loft and the legacy fields above are ignored
│                         for that piece. See the multisection guide.
├── wheelhouses           wheel_house_axial_clearance_mm,
│                         wheel_house_lateral_clearance_mm,
│                         front_steering_clearance_mm, rear_steering_clearance_mm,
│                         front_wheel_house_fillet_mm,  rear_wheel_house_fillet_mm,
│                         lateral_clearance_overrides_mm  (per-corner dict)
├── alignment             camber_front_deg, camber_rear_deg,
│                         toe_front_deg, toe_rear_deg
└── wheel: WheelSpec
    ├── tire:  TireSpec   (section_width, aspect_ratio, rim_diameter_in,
    │                       sidewall_bulge, shoulder_radius, tread_width,
    │                       crown_radius, rim_flange)
    └── spoke: SpokeSpec  (wheel_width, hub_bore, wheel_offset (ET),
                           dish_depth, num_spokes, spoke widths, window gaps,
                           rim_band_width, spoke_thickness, ...)

# Optional: separate rear wheel
UnderbodySpec.rear_wheel = WheelSpec(...)  # None -> reuse front wheel

Common tweaks

Legacy angle + radius diffuser

from paramub import generate, UnderbodySpec, WheelSpec, TireSpec, SpokeSpec

spec = UnderbodySpec(
    wheelbase_mm=2900,
    ride_height_mm=80,
    diffuser_angle_deg=10,
    front_wheel_house_fillet_mm=150,
    wheel=WheelSpec(
        tire=TireSpec(section_width_mm=265, aspect_ratio=35, rim_diameter_in=20),
        spoke=SpokeSpec(num_spokes=10, wheel_offset_mm=45),
    ),
)
generate(spec, output_dir="outputs/sport", stem="sport", output_mode="all")

Multisection splitter + diffuser

from paramub import (
    generate, UnderbodySpec, WheelSpec, TireSpec, SpokeSpec,
    DiffuserSection, SplitterSection,
)

spec = UnderbodySpec(
    wheelbase_mm=2700.0,
    floor_width_mm=1800.0,
    splitter_sections=[
        SplitterSection(y_mm=0,   kick_x_mm=1450, front_x_mm=2200,
                        front_z_mm=150, front_angle_deg=5,
                        start_strength=0.30, end_strength=0.30),
        SplitterSection(y_mm=900, kick_x_mm=1400, front_x_mm=2200,
                        front_z_mm=180, front_angle_deg=8,
                        start_strength=0.25, end_strength=0.25),
    ],
    diffuser_sections=[
        DiffuserSection(y_mm=0,   kick_x_mm=-1350, rear_x_mm=-2150,
                        rear_z_mm=200, rear_angle_deg=8,
                        start_strength=0.37, end_strength=0.37),
        DiffuserSection(y_mm=900, kick_x_mm=-1200, rear_x_mm=-2150,
                        rear_z_mm=300, rear_angle_deg=12,
                        start_strength=0.21, end_strength=0.26),
    ],
)
generate(spec, output_dir="outputs/multi", stem="multi",
         output_mode="all", output_parts=True)

Standalone Bezier primitives

The cubic Bezier construction used by the splitter and diffuser is exposed in two reusable layers, independent of the underbody: 

from paramub import cubic_bezier_edge, cubic_bezier_from_tangents
import cadquery as cq

# Layer 1 — explicit 4-point cubic Bezier:
edge = cubic_bezier_edge(cq.Vector(0,0,0), cq.Vector(100,0,0),
                          cq.Vector(150,0,80), cq.Vector(200,0,100))

# Layer 2 — endpoints + outgoing tangents + relative handle strengths:
edge = cubic_bezier_from_tangents(
    p0 = cq.Vector(0, 0, 0),
    p3 = cq.Vector(200, 0, 100),
    t0 = cq.Vector(1, 0, 0),          # leaves P0 along +X
    t3 = cq.Vector(0, 0, 1),          # arrives at P3 going +Z
    start_strength = 0.4,             # |P0-P1| = 0.4 * |P3-P0|
    end_strength   = 0.4,
)

Reconstructed-car pipeline (end to end)

If you start from a reconstructed whole-car mesh (UltraShape / Hunyuan3D) and want a watertight body + parametric UB, you have two paths:

  • One-shot: make_pipeline.py (or its Slurm wrapper make_pipeline.sbatch) runs all four stages on one raw input, tees every stage's stdout into a master log and a per-stage log, and writes a consolidated summary JSON. See below.
  • Manual: run the four stage drivers in order, each writing into a sibling outputs/ subdirectory. See the per-stage subsections below for the algorithm details.

One-shot orchestrator

conda activate paramub

# Login node (caps Stage 4 at small depth to fit in 4 GB):
python make_pipeline.py \
    --input data/<base>.stl \
    --skip-watertight

# Production — Slurm wrapper requests 128 GB / 8 CPU / 4 h, runs all 4:
sbatch make_pipeline.sbatch data/<base>.stl

Produces:

  • outputs/shell/<base>_* — stage 1 outputs
  • outputs/integrate/<base>_* — stages 2 / 3 / 4 outputs (shell + UB + 4 wheels + gap + combined + fixed + clean + per-corner clean + JSON verify reports)
  • outputs/integrate/<base>_summary.json — consolidated summary: all the geometry knobs the parametric UB used (wheel centres, tire spec, wheelhouse heights, splitter / diffuser sections, floor z), plus the geometric outputs of the final watertight result (dimensions, triangle counts, watertight flags, volumes per body and per wheel, aggregate totals).
  • logs/<base>_pipeline.log — single master log with section banners for each stage; mirror of all stage stdout
  • logs/<base>_stage_<n>_<name>.log — per-stage log (one file per driver, easier to grep for one stage's output)

Per-stage flags can be forwarded after the input. The orchestrator also exposes --skip-shell, --skip-integrate, --skip-fillgap, --skip-watertight for partial reruns.

Manual stage-by-stage

Each stage writes into a sibling outputs/ subdirectory; the next driver picks up from there. 

conda activate paramub
BASE=outputs

# 1. Extract the upper-body shell.
python run_shell.py \
    --input data/car.stl \
    --output-dir $BASE/shell
# → $BASE/shell/car_final.stl  +  car_meta.json

# 2. Drop in the parametric underbody (anchored splitter + diffuser),
#    aligned to the shell frame and trimmed to the shell rim.
LD_LIBRARY_PATH=$CONDA_PREFIX/lib python integrate_underbody.py \
    --shell-meta $BASE/shell/car_meta.json \
    --output-dir $BASE/integrate
# → $BASE/integrate/car_{shell, underbody, underbody_trimmed,
#                         cut_polygon, wheel_*, integrate_meta}.{stl,json}

# 3. Close the shell ↔ UB rim ribbon and (optionally) repair + remesh
#    the combined mesh.
LD_LIBRARY_PATH=$CONDA_PREFIX/lib python fill_gap.py \
    --shell $BASE/integrate/car_shell.stl \
    --ub    $BASE/integrate/car_underbody_trimmed.stl \
    --out          $BASE/integrate/car_gap.stl \
    --combined-out $BASE/integrate/car_combined.stl \
    --repair --repair-close-holes-max 10000 \
    --repair-remesh-mm 6 --repair-remesh-iters 3
# → $BASE/integrate/car_gap.stl       (ribbon mesh alone)
# → $BASE/integrate/car_combined.stl  (shell + UB + ribbons, repaired)

# 4. Smooth-dual-contouring remesh + symmetry + cleanup → strictly
#    watertight body STL, plus a trimesh-only fill_holes pass on each
#    of the 4 adjacent wheel STLs. Defaults to depth 11 (production);
#    submit via the Slurm wrapper since the Blender peak is ~96 GB.
sbatch make_watertight.sbatch \
    $BASE/integrate/car_combined.stl  car
# → $BASE/integrate/car_fixed.stl                       (Blender stage output)
# → $BASE/integrate/car_clean.stl                       (watertight body)
# → $BASE/integrate/car_clean.json                      (body verify report)
# → $BASE/integrate/car_wheel_{FL,FR,RL,RR}_clean.stl   (4 watertight wheels)
# → $BASE/integrate/car_wheel_{FL,FR,RL,RR}_clean.json  (per-wheel reports)
LD_LIBRARY_PATH=$CONDA_PREFIX/lib is needed wherever PyMeshLab is invoked (step 2's remesh, step 3's --repair pass). Drop it (and pass --no-remesh / omit --repair) to run on the default system Python lib path.

Step 1 — shell extraction

See the shell_extract guide for the full seven-step walkthrough with per-step renders, the visibility classifier, the cut-zone guard, and all tuning knobs.

Step 2 — integrate parametric UB

integrate_underbody.py measures the shell's front and rear edges at chosen Y values, anchors a multisection splitter + diffuser to those measurements, generates the underbody at the shell's scale, transforms it into the shell frame, takes the left half, and trims its perimeter to the shell's lower silhouette.

See the docstring of integrate_underbody.py for the full pipeline (frame conventions, anchor measurement, spec construction, boundary trim). For a per-parameter reference of where each value comes from (detected vs heuristic vs hard-coded vs default), see the parameter provenance page.

Step 3 — close the shell ↔ UB gap

After step 2 the shell and trimmed UB meet at a thin open seam along the rocker line and around each wheel arch. fill_gap.py closes it with shared-slant bipartite-zip ribbons:

  1. Per UB rim vert, build one subdivided slant to its nearest shell-rim vert at ~target_edge_mm spacing (auto-picked from the shell's median edge length, typically ~6 mm). Slant verts are reused by both adjacent ribbons.
  2. Per UB rim edge, bipartite-zip the two slants into one triangle per zip step — no wedge holes between ribbons.
  3. The shell-side polygon holes (where the apex chain skips shell verts) are sealed by the optional --repair + --repair-remesh-mm pass.

Recommended one-shot recipe for a watertight result is in the end-to-end snippet above. The fill_gap guide has the algorithm details, all tuning knobs, and known limits.

Step 4 — strictly watertight finisher (body + 4 wheels)

Step 3 produces a closed mesh, but the combined STL still has a handful of non-manifold edges (apex-sharing in the ribbon strip, plus close_holes residuals), inconsistent face winding, and hundreds of disconnected micro-bodies from STL float round-trip. Real CFD / 3-D-print toolchains reject meshes like that. make_watertight.py turns it into a strictly watertight single body, then also runs a fast trimesh-only finisher on each of the 4 wheel STLs adjacent to the input:

  1. Stage A (Blender, bpy 4.2): import STL → Smooth Remesh modifier (dual-contouring at octree depth 11) → keep largest component → merge / dissolve / fill_holes / normals consistent → symmetrize at y=0 → iterative delete-non-manifold-and-refill loop → export <tag>_fixed.stl.
  2. Stage B (trimesh): split by connected components, keep the biggest (drops 2-6 face Blender-STL micro-strays from float32 vertex rounding), verify is_watertight == True / is_winding_consistent == True / len(split()) == 1, write <tag>_clean.stl + JSON report.
  3. Wheels (trimesh only): each <base>_wheel_<corner>.stl goes through fill_holes + biggest-body + verify. CadQuery-tessellated wheels are already consistent-winding and single-component; only ~6 chord-discretization open edges need closing per wheel. Mean distance to the source wheel STL is ≈ 1e−12 mm. Pass --no-wheels to skip this stage.

At depth 11 (recommended for production) the Blender peak is ~96 GB on a ~4.5 m car — use the Slurm wrapper rather than the login node. Lighter depths (8–9) run comfortably in < 8 GB. See the watertight guide for the depth-vs-fidelity table, all tuning knobs, and known limits (including how to handle non-Y symmetry axes and Genus > 0).
