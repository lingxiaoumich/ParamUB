User guides

ParamUB — parametric wheel + underbody generator

Six builders compose into one car-underbody assembly. Builders 1–2 feed builder 3 (wheel); builders 4–5 plus four wheels feed builder 6 (underbody). Wrapped around that, a four-stage pipeline turns a reconstructed whole-car mesh into a strictly watertight body + UB solid: shell extraction peels the upper body off the input mesh, integrate_underbody.py drops in the parametric underbody and trims it to the shell silhouette, fill_gap.py closes the residual ribbon between the two rims, and make_watertight.py runs a smooth-dual-contouring remesh + symmetry + non-manifold cleanup that produces a single closed body ready for CFD / 3-D printing / volume computation.

Full pipeline (reconstructed car → watertight body)

Four stage drivers, plus a master orchestrator (make_pipeline.py / make_pipeline.sbatch) that runs all four in order, tees stdout into one log per stage and one master log, and writes a consolidated <base>_summary.json with every geometry knob the parametric UB used alongside the verify metrics of the final watertight result.

Unified entry — generate

A single function takes one combined spec and writes either an STL file or a full bundle (STL + 5-view PNGs + composite preview + log + parameter JSON). The user guide has full examples; the short form: 

from paramub import generate, UnderbodySpec

# Just the STL
generate(UnderbodySpec(), output_dir="out", stem="ub", output_mode="stl")

# Full bundle: STL + view PNGs + composite preview + log + spec.json
generate(UnderbodySpec(), output_dir="out", stem="ub", output_mode="all")
The renderer runs in a subprocess (PyVista / OCP llvmpipe conflict). See paramub/_render_views.py.

Integrating with a reconstructed shell

integrate_underbody.py at the repo root ties the generator to the full-car upper shell extracted by run_shell.py:

  1. Probe the shell at Y = 0, Y = front_wheel_y and Y = rear_wheel_y for the front- and rear-bumper-bottom anchors (measure_shell_anchors picks the lowest-z vertex in a 200 mm-deep band at each end).
  2. Build a 3-section multisection splitter + diffuser loft pinned to those anchors (Y0 = centerline, Y1 = wheel center, Y2 outboard section reuses Y1's shape).
  3. Run build_underbody(spec) on the full car, transform into the shell frame (mirror +X about the wheel midpoint).
  4. BREP cut: extrude the shrunk shell-rim polygon vertically and intersect each CadQuery face with it (BRepAlgoAPI_Common) so the cut boundary becomes an analytical curve before STL tessellation. Default shrink 100 mm (configurable via --cut-shrink-mm).
  5. Isotropic remesh the trimmed underbody to roughly the shell's median edge length using PyMeshLab's meshing_isotropic_explicit_remeshing.

Outputs in --output-dir: _shell.stl, _underbody.stl (untrimmed), _underbody_trimmed.stl (BREP-cut + remeshed), _cut_polygon.stl (debug wall), four _wheel_*.stl, and _integrate_meta.json. 

LD_LIBRARY_PATH=$CONDA_PREFIX/lib python integrate_underbody.py \
    --shell-meta outputs/shell/<name>_meta.json \
    --output-dir outputs/integrate

The LD_LIBRARY_PATH override is needed for PyMeshLab. Pass --no-remesh to skip the final remesh and run with the default system Python lib path.

Closing the gap — fill_gap.py

Step 2 leaves an open ribbon between the shell rim (~3.7 k boundary verts around the rocker line and wheel arches) and the UB rim (~1.9 k boundary verts on the underbody's trimmed perimeter). fill_gap.py triangulates that ribbon with shared-slant bipartite-zip ribbons:

  1. Per UB rim vert u_j: pick its apex shell-rim vert (nearest in 3-D); subdivide the slant u_j → apex_j at ~shell median edge length (~6 mm). Slant verts are stored ONCE and reused by both adjacent ribbons.
  2. Per UB rim edge (u_j, u_{j+1}): bipartite-zip slant[j] ↔ slant[j+1] into one triangle per zip step. Shared slant verts ⇒ no wedge holes between ribbons.
  3. Combined mesh: shell + UB + ribbons concatenated. UB-side boundary is watertight; the shell side has intentional polygon holes where the apex chain skips over shell-rim arcs.
  4. Optional --repair pass: PyMeshLab merge_close_vertices → repair_non_manifold_edges → close_holes (+ optional isotropic remesh) seals those polygon holes. --repair-remesh-mm 6 evens out the fan triangulation that close_holes leaves behind.
LD_LIBRARY_PATH=$CONDA_PREFIX/lib python fill_gap.py \
    --shell outputs/integrate/<name>_shell.stl \
    --ub    outputs/integrate/<name>_underbody_trimmed.stl \
    --out          outputs/integrate/<name>_gap.stl \
    --combined-out outputs/integrate/<name>_combined.stl \
    --repair --repair-close-holes-max 10000 \
    --repair-remesh-mm 6 --repair-remesh-iters 3

See the fill_gap guide for tuning knobs and known limits.

Watertight finisher — make_watertight.py

fill_gap.py --repair --repair-remesh-mm 6 already produces a mesh with zero open edges, but it can have a handful of non-manifold edges (apex-sharing ribbons, close_holes fan residuals), inconsistent face winding, and hundreds of tiny disconnected bodies from the STL float-round-trip. Real CFD / 3-D-print toolchains refuse meshes like that. make_watertight.py is the robust finisher: it runs a smooth dual-contouring remesh in Blender (bpy 4.2) + Y-symmetry + iterative non-manifold cleanup, then extracts the largest connected body in trimesh and verifies is_watertight == True, is_winding_consistent == True, len(split()) == 1. 

# Production — default depth 11 (~96 GB peak, ~25 min, ~0.4 mm error):
sbatch make_watertight.sbatch \
    outputs/integrate/<name>_combined.stl \
    <tag>

# Login-node sanity check at depth 8 (~4 GB peak, ~15 s, ~0.8 mm error):
python make_watertight.py \
    --input  outputs/integrate/<name>_combined.stl \
    --output outputs/integrate/<name>_clean.stl \
    --depth 8

Outputs for the body: <tag>_fixed.stl (Blender stage), <tag>_clean.stl (final), and <tag>_clean.json (verify report with watertight / Euler / volume / surface-distance metrics). The 4 adjacent wheel STLs (<base>_wheel_<corner>.stl from stage 2) are also processed through a fast trimesh-only fill_holes + verify pass, producing <tag>_wheel_<corner>_clean.stl + .json for each. See the watertight guide for the depth-vs-fidelity table, Slurm sizing, and tuning knobs.
