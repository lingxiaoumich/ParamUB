Reference

Parameter provenance — detected vs default vs user-specified

For each parameter that drives the parametric underbody (stage 2), where does its value come from? This page is the reference when you expand the pipeline to a new car and want to know which knobs are learned from input geometry, which are hard-coded defaults you might want to tune, and which the CLI already lets you override.

Overview — the four provenance categories

ProvenanceSourceHow to tune
Detected Computed from the input shell mesh + stage-1 meta JSON in integrate_underbody.extract_hints(). Change the input. If the detection is wrong on a new car, fix extract_hints() (heuristics live there).
Heuristic Computed inside integrate_underbody.build_spec() as a function of detected hints (e.g. crown_radius = f(tire_width, tire_OD)). Tweak the formula in integrate_underbody.build_spec().
Hard-coded A literal in integrate_underbody.build_spec() that overrides the dataclass default (e.g. wheel_house_axial_clearance_mm=20.0). Edit the literal in integrate_underbody.build_spec(); or expose it as a CLI flag.
Default Falls through to the dataclass default in paramub/builders/{ub_assem, floor, wheelhouse, wheel, spoke, tire}.py. Edit the dataclass default, or override in integrate_underbody.build_spec().

1. Geometry hints (detected from shell mesh)

Computed by integrate_underbody.extract_hints(shell_mesh, meta, scale) and stored in <base>_integrate_meta.json under the "hints" key. They are derived from the shell vertices + the per-wheel fits (centre / radius / axial half) that stage 1's shell.extract wrote to <base>_meta.json.

Shell anchors (per Y target)

In addition to the hints above, integrate_underbody probes the shell at three Y targets — 0, front_wheel_y, and rear_wheel_y — for the lowest-z shell vertex in a 200 mm-deep band at the front and rear ends. The resulting front_z_shell / rear_z_shell numbers anchor the splitter/diffuser Z heights at each section. Stored in integrate_meta.json["shell_anchors"].

2. Tire + spoke (detected with heuristics)

Built in integrate_underbody.build_wheel_spec() from the detected tire_od_mm + tire_width_mm. Most fields are heuristic formulas of those two; the rest are hard-coded for now.

3. Splitter / diffuser sections (anchored to shell)

Three sections each, at y = 0, y = front_wheel_y, and y = body_half × 0.95. Built in integrate_underbody.build_splitter_sections() and build_diffuser_sections(). Each section has 4 detected endpoints (x and z, at front + rear) and 3 hard-coded knobs (kick x, edge angle, Bezier handle strengths).

FieldProvenanceValue
y_mmDetected 0, front_wheel_y, 0.95 × body_half
Splitter front_x_mm / front_z_mm Detected Front-end shell anchor at this Y (shell_anchors[y] .front_x_shell / .front_z_shell).
Diffuser rear_x_mm / rear_z_mm Detected Rear-end shell anchor at this Y.
kick_x_mm (splitter / diffuser) Hard-coded splitter: +1450 mm; diffuser: −1400 mm (where the flat-floor floor transitions into the angled splitter / diffuser).
front_angle_deg / rear_angle_deg Hard-coded splitter 5°; diffuser 5°
start_strength / end_strength Hard-coded 0.30 for both pieces (Bezier handle length as a fraction of the chord).

5. CLI / runtime overrides

Currently the user-facing CLI surface is small — the whole UnderbodySpec is auto-derived. Existing flags:

FlagDriverEffect
--input / --output-dir all 4 stages File paths.
--shell-meta integrate_underbody.py Path to stage-1 meta JSON (default: alfa example).
--no-trim integrate_underbody.py Skip the BREP-cut trim of the parametric UB to the shell rim.
--no-remesh integrate_underbody.py Skip the post-trim isotropic remesh.
--cut-shrink-mm integrate_underbody.py Shrink the cut polygon by this many mm before trimming (default 100). Larger = more UB stays inside the rim.
--depth / --max-nm-passes / --no-symmetrize / --wt-mode / --include-wheels / --no-wheels make_watertight.py / make_pipeline.py Stage-4 tuning (see watertight guide).
--repair + --repair-close-holes-max / --repair-remesh-mm / --repair-remesh-iters fill_gap.py Stage-3 close_holes + isotropic remesh on the combined mesh.

None of the UnderbodySpec fields above (clearances, fillets, alignment, splitter/diffuser angles, …) currently has a CLI flag — they're hard-coded in integrate_underbody.build_spec(). If your new car needs a different value, edit that function (one literal per field, all in one place between lines 481-501).

Extending to other cars — recommended knobs

Most parameters are detected from geometry, so a new car typically needs zero changes to the spec construction code. The pipeline should produce a sensible parametric UB on any input the shell extractor can handle. Things that may need attention:

  1. Scale normalisation. TARGET_WHEELBASE_MM = 2700 is the assumed real-world wheelbase used to derive the shell-to-mm scale. If your input STL is already in mm at real size, the scale will come out as 1.0 and everything's fine. If the input is in normalized units (e.g. Hunyuan3D output), the scale assumes the car is a 2.7 m wheelbase sedan. For very different wheelbases (super-cars, vans), you may want to set TARGET_WHEELBASE_MM per car or skip the rescale.
  2. Wheelhouse clearances. The hard-coded axial_clearance_mm = 20 and lateral_clearance_mm = 25 work for typical passenger cars. SUVs / off-road may want more axial; track cars may want less. Exposing as CLI flags is easy (one-line argparse + thread through build_spec()).
  3. Splitter / diffuser angles. Hard-coded at 5° front and 5° rear. Performance cars may want steeper diffusers (8-15°). The Bezier handle strengths (start_strength = end_strength = 0.30) also affect the curve shape — softer (0.2) or sharper (0.5) reshape the transition without changing endpoints.
  4. Wheel design. The visible wheel spokes / hub bore / offset are pure SpokeSpec defaults (the shell extractor removed the real wheels, so we have no detection signal). If you want the rendered wheel to match the source car, override spoke = in build_wheel_spec().
  5. Multi-axle / non-symmetric vehicles. The detection assumes track_front = track_rear. Cars with very different tracks (some sports cars, some EVs) would want per-axle detection. The hooks are already there — change track_front_mm and track_rear_mm in build_spec() to use per-axle hints.
